# UI/UX Rules

## Core rules

1. One title per screen.
Do not repeat the same context in a second header inside the page.

2. Short forms use one working surface.
Do not split a short form into multiple cards unless the groups are truly different.

3. Long forms may use sections, but each section must be necessary.
Use section titles only for meaningful groups such as personal data, contact, allergies, SOAP, prescriptions.

4. Reduce explanatory copy.
Only keep helper text when it changes a decision or prevents an error.

5. Primary actions must be singular.
There should be one clear primary action per screen. Secondary actions should be quieter.

6. Secondary fields must look secondary.
Optional notes, advanced settings, or infrequent fields should be collapsed, moved down, or visually softened.

7. Use controls according to task frequency.
Searchable selector for large lists, simple select for small option sets, direct buttons only for a few high-frequency choices.

8. Avoid nested containers.
Do not place cards inside cards or create header inside header patterns.

9. Prefer compact density for clinical work.
Use less decorative spacing and reserve large vertical gaps for true separation.

10. Administrative content must not compete with clinical content.
Clinical context and immediate action come first. Configuration, export, and metadata come later.

## Applied patterns

- Screen title line: back action plus one title, no extra subtitle unless strictly needed.
- Short form layout: one container, fields in sequence, actions at the end.
- Long form layout: one title line, section headers only where grouping is real.
- Optional notes: collapsed or visually secondary by default.
- Dashboard blocks: no repeated summary strips if the same data appears in the body.
